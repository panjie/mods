# 命令分析与审批变化（2026-10-25）

命令分析已集中到独立模块，共享解析与命令语义。审批依据明确的读取来源、写目标和目标覆盖证据；候选路径和工作目录不会自动变成写权限。

## 支持改善

- uniq 的数字参数与输出角色、touch 的参考/时间参数及已声明的组合短选项。
- 普通非递归 cp/mv 在文件类型、链接和文件系统证明成立时可复用目标规则；复制要求目的写权限，移动要求两端。
- 安全环境赋值下的受限 env 写入继承内层目标与操作类型。
- Git 支持受限全局选项和只读前序上下文；配置注入、hook/helper 效果仍要求审批。
- PowerShell 内容写使用一个明确标量路径；字面重定向必须有完整 AST 节点、所属命令、流和目标证据。
- 目标在执行前变化会重新审批；持续变化停止执行。

## 有意保守的行为

未知命令/选项、动态或不完整写目标、未建模的递归、链接、跨卷、复杂 PowerShell 数组/splat/provider、任意 wrapper 或 Git helper 不能借用已有规则或临时目录豁免。find 批量执行不会把 uniq/xxd 的单输入只读结论套用到多个操作数。

date/hostname 的修改形式、unlink 多操作数，以及 PowerShell 未绑定路径/未知参数等旧宽松判断已收紧。没有新增权限模式、持久化规则类型或模型分类请求；复杂命令仍直接进入普通效果/目标审批，不要求改写或消耗重试预算。

## 验证与限制

Linux 构建、全量测试、race、计数快照和三组 fuzz 通过；Linux PowerShell 7.6.8 完成真实解析与隔离执行验证。2026-10-26 补齐 Windows 全量测试、PS7/PS5.1 真实解析与隔离执行、junction 边界和平台计数快照，见 [Windows 验收记录](superpowers/plans/2026-10-26-command-analysis-windows.md)。Windows cp/mv 文件身份与卷证明仍保持未支持；UNC、Windows race 和 macOS 实机验收仍有缺口。

固定构造样本观察到审批改善，不能据此宣称真实用户误报率下降。分析不是操作系统沙箱，也不能消除批准与文件系统调用之间的所有竞态。详细证据见 [第六阶段记录](superpowers/plans/2026-10-25-command-analysis-stage6.md)。
