# AGENTS.md

## Commands
- `go run github.com/go-task/task/v3/cmd/task@v3.51.1 build` writes `bin/mods` or `bin/mods.exe` with git version metadata.
- Pre-PR baseline from README/CI: `go run github.com/go-task/task/v3/cmd/task@v3.51.1 check` (`go build ./...`) then `go run github.com/go-task/task/v3/cmd/task@v3.51.1 test` (root module). To mirror CI exactly, run `go run github.com/go-task/task/v3/cmd/task@v3.51.1 ci` (verbose root-module build/tests with coverage).
- Focus a normal test with `go test ./internal/app -run TestName -count=1` or the relevant package path.
- Command-analysis migration baseline: `go test ./internal/app -run '^TestCommandAnalysisBaseline$' -count=1`; parser/bridge/Git work counts use `go test -tags commandtrace ./internal/app -run '^TestCommandAnalysisWorkBaseline$' -count=1`. Fixtures and measured platform snapshots live in `internal/app/testdata/command_analysis`; `-update-command-baseline` records observations, never changes the independent safety assertions. Stage-2 counts use `work_stage2_<os>.json`; preserve the original `work_windows.json`. The work harness asserts one main parse even without a platform snapshot. Review all snapshot differences; see `docs/superpowers/plans/2026-10-23-command-analysis-baseline.md` for scope and limitations.
- Stage-6 boundaries: `go test ./internal/app -run TestCommandArchitectureHasOneProductionBoundary` and the recursive analysis import guard. Fuzz targets in `internal/commandanalysis/stage6_properties_test.go` cover parser/composition, unknown options, literal argv and stable merging; run each with `go test ./internal/commandanalysis -run '^$' -fuzz '^<target>$' -fuzztime=10s -parallel=2`. Optional real bridge cold/warm benchmarks use `MODS_TEST_PWSH=/path/to/pwsh go test ./internal/commandanalysis -run '^$' -bench BenchmarkPowerShellBridgeLifecycle -benchtime=5x`. Cross-compilation never counts as a real Windows/macOS run.
- Build task install-path tests live in `internal/buildtask`; run `go test ./internal/buildtask -run TestInstallDir -count=1` after touching `Taskfile.yml` or install-path logic.
- Provider integration tests are excluded by default; run `go test -tags integration ./internal/app -run TestOpenAIIntegration -count=1` only with the matching provider key. Ollama integration uses `OLLAMA_HOST` or `http://localhost:11434` and model `llama3.1`.
- The golden test in `internal/proto` updates with `go test ./internal/proto -run TestStringer -update`.
- Score a saved session against the diagnosis rubric with `go run ./internal/evals/cmd/score -db ~/.local/share/mods/sessions/mods.db -session <id-prefix> -case ambiguous-symptom`. The command copies the database before opening it; `-json` and `-strict` are available for scripts. Rubric cases and limits live in `internal/evals/score.go`.
- Lint config is `.golangci.yml` v2; local lint is `golangci-lint run ./...` if installed. It enables `govet` and `ineffassign` linters, the `gofmt` and `goimports` formatters, and sets `run.tests: false`.

## Architecture
- Entry path is `main.go` -> `internal/cli.Run` -> Cobra root in `internal/cli/main.go`; `execute` loads settings with `config.Ensure` and initializes flags after config; parsed database actions call `ensureSessionDB` lazily. Help/version, configuration and non-session listings avoid session storage. Existing-config `--no-save` prompts skip the DB unless continuing a session; first-run setup still checks session history.
- Configuration UI: `internal/cli/setup_model.go` owns the Bubble Tea page state and per-provider drafts; `setup_async.go` returns versioned messages for discovery/auth/connection checks; `setup_view.go` renders shared interaction styles. `configure.go` retains configuration and provider helpers. Network commands must never mutate drafts directly.
- Native image search: `internal/tools/image_scan.go` and `image_tools.go` provide paginated `fs_find_images` and `fs_read_images`. `proto.ToolResult` / `Request.ResultCaller` preserve image bytes and source labels; legacy text callers remain supported. Chat Completions/Ollama project tool images into a user attachment message after the full tool-result group, while Responses/Anthropic use native tool-result image blocks. `stream.ValidateImageWireRequest` bounds cumulative images and request size; the app reserves history in the image registry and reports incomplete scans. Media capabilities describe adapter protocol support, not model understanding. Do not add model-name media allowlists or per-model capability settings; the service decides whether a model accepts media.
- Runtime is `internal/app.Mods` (Bubble Tea): stdin/cache handling, provider selection, streaming, tool calls, and review prompts.
- Provider-neutral contracts are `internal/proto` and `internal/stream`; provider adapters live in `internal/openai`, `internal/anthropic`, `internal/google`, and `internal/ollama`. OpenAI-compatible providers route through `internal/openai`.
- Tool wiring is `internal/tooling.BuildRegistry`: native tools in `internal/tools`, MCP in `internal/mcpclient`, review rules in `internal/approval`. Every built-in is declared once in `internal/tooling` `builtinTools()` (registration + runtime `enabled` policy); both the runtime registry and the `--list-tools` catalogue (`BuiltinSpecs`) walk that table, so adding a built-in is one table entry. Tools are supported for OpenAI-compatible, Anthropic, and Ollama; Google skips implicit auto filesystem tools and errors when tools are explicitly enabled.
- Config defaults are generated from embedded `internal/config/config_template.yml`; when adding a setting, update the config structs, `Help` map, template, and config tests together. `TestSelfHelpSettingsCoverEveryPersistentConfigKey`, `TestConfigTemplateCoversEveryPersistentSetting` and `TestConfigTemplateUsesOnlyDocumentedHelpKeys` fail when one of those places is missed, so the drift shows up as a test failure rather than an undocumented key.
- CLI flags are declared once in `internal/cli/flags.go` `flagCategorySpecs` (`flagSpec`: usage order, category, tier, and one-shot role bits), with registration in `registerFlags`. `isNoArgs`, `hasChatSessionAction` and the first-run auto-config skips derive from those role bits. `TestFlagTableMatchesRegistration` fails when the table and the registrations disagree, and `TestOneShotRoleAssignments` locks which flags carry each role.
- Conversation history and saved approval rules persist in a SQLite DB under the configured cache path; schema changes belong in `internal/session/db.go` migrations and legacy tests.
- Approval/review subsystem (security-critical): `internal/app/review.go` `toolReviewer.requestApproval` gates every tool call. Reads proven statically or explicitly trusted run without review, including external and dynamic-path reads. Writes require complete target coverage before saved rules or temporary exemptions can apply. Non-temporary writes are approved by target: explicit-write `DirAllow` rules cover a local directory subtree, while `RemoteAllow` rules exactly match normalized origins. Empty-mode and read-mode legacy directory rules do not authorize writes. `auto` honors session rules, `always` ignores them, and `never` bypasses review. Matching lives in `internal/approval/matching.go`; the access matrix and target model live in `internal/approval/access.go`.
- `RuleSet` only stores/deduplicates rules. Authorization goes through `requestApproval` → `ClassifyAccess` / `RulesAllowIntent`; do not add tool-name or shell-prefix permission matchers. Legacy `EditAll`, `ToolAll`, `ShellPrefix`, and `ShellExact` rows remain readable/persistable but grant no permission. Gate and dispatch regressions live in `internal/app/approval_entrypoint_test.go`; path-matching fixtures do not require a PowerShell host, while shell parsing remains covered by assessment/conformance tests.
- Shell classification: `internal/commandanalysis` owns POSIX AST / PowerShell IR / literal argv analysis; `internal/app/command_analysis.go` adapts tool inputs, config and process bindings and shares `commandResultToIntent` between initial review and revalidation. The analyzer returns facts with explicit evidence, write-target coverage, and gap codes (`internal/commandanalysis/facts.go`; shared policy evidence vocabulary in `approval/evidence.go`). Incomplete writes never reuse rules or the temporary-directory exemption. There is no LLM classifier, advice model, analysis cache, or classifier prompt. Unknown effects proceed to ordinary approval unless opt-in `command-simplification: once` returns its single typed, not-executed organization result for a narrow high-confidence built-in candidate; replacement calls still require fresh analysis and ordinary authorization. AST/IR directory facts remain authoritative; literal extraction may only add external directories. Leaf write operands are preserved for real-path checks. Git push resolution enumerates invocations, reads all push URLs (including URL rewrites), and separates local remotes from network origins. Unmodeled hooks/helpers keep Git writes incomplete. Stable environment materialization does not by itself prove complete target coverage. Assessment/conformance tests pin these invariants.
- Startup: interactive terminal probing overlaps session lookup, but lookup results/errors are held until the background reply or timeout. Raw output constructs Markdown renderers only on demand. `--debug` reports configuration, DB, app, terminal, session, provider, context, tools, request-ready and first-response durations.
- Chat MCP transport reuse is scoped by `mcpclient.WithSessionPool` to one chat invocation. Registries/approvals remain per request; reused connections refresh tools and annotations each turn. Config/environment changes and transport errors retire connections; tool calls are never replayed automatically. Closing the chat cancels all pooled transports. Single-turn invocations retain request-scoped cleanup.
- Runtime skill catalogs use `skills.ScanCatalogDirs` (bounded metadata cache invalidated by file identity/size/mtime); `Skill.LoadBody` reads current instructions on demand. Full `Scan`/`ScanDirs` remain available to callers needing bodies. Tool catalog registration performs no filesystem probes and cannot execute callbacks.
- Command analysis tests live in `internal/commandanalysis`; app retains approval/dispatch and full-pipeline conformance tests. `approval/command_compat.go` and its legacy `AccessIntent()` conversion are removed; callers import analysis facts/helpers directly. `approval/evidence.go` only shares tool-neutral coverage/gap vocabulary. `internal/cli/main.go` defers `commandanalysis.CloseBridge()` for CLI bridge cleanup. The phase-2 engine shares one AST/IR per Analyze (`parsed.go`), snapshots environment and exposes bounded read-only host interfaces (`dependencies.go`, `host.go`). Initial review and revalidation propagate analysis cancellation/errors before dispatch. PowerShell IR v2 records node/argument/redirection metadata without enabling new write coverage; bridge connections track host/environment identity. Mutable query results are never reused across Analyze calls. Stage 3 routes command rules through `catalog_entries.go` (identity, grammar, compatibility revision, tests); readonly/write/coverage wrappers only delegate. `semantics.go` evaluates each AST/IR invocation once per assessment and shares facts with coverage, reviewability, trust comparison and Git enumeration; nested wrappers share bounded evaluation results. Registry construction performs no I/O or rule evaluation. Native processes do not inherit PowerShell aliases or POSIX-only builtins; executable suffixes cannot inherit cmdlet reads. `testdata/catalog_legacy.json` is immutable pre-migration evidence, with independent safety tests for intentional tightening. Stage 4 authorizes commands only through `app.commandResultToIntent` consuming `Result.Targets` (`targets.go`): role/kind/operation, lexical and resolved leaf, authorization directory, state and node identity. KnownDirs is display-only; literal fallback is candidate-only and never enters write rules. Follow-leaf writes resolve the leaf; remove/rename/create entries resolve the parent; mkdir creation also requires the existing ancestor via the bounded optional `CreationParentResolver`. Unknown destination forms remain incomplete. Preserve non-nil empty write groups during normalization, or mixed reads can hide unknown writes. `TargetBindings` pins leaf identities for command revalidation; diagnostics/candidates/read-only changes do not trigger write reapproval, and fresh read context is retained. Command UI distinguishes read sources, writes, candidates and unresolved portions. All command authorization tests use the production `commandResultToIntent`; no KnownDirs-based compatibility converter remains. Stage-4 observations live in `baseline_stage4_<os>.json`; original platform snapshots remain immutable. Stage-5 observations use `baseline_stage5_<os>.json`. Ordinary native cp/mv require the optional fresh `TransferResolver` proof (regular single-link files, no symlink components, same filesystem); failure stays incomplete. Strict file options and numeric uniq options use catalog binding. Git context-preserving reads require audited built-in facts and a plain AST without assignments/redirections. Batched find exec cannot inherit operand-sensitive read semantics (uniq/xxd). Stage-5 extensions bind touch reference inputs as reads, audited flag bundles, and safe env wrappers that preserve inner target operations. Git global options share `bindGitGlobals`; config injection and helper effects remain incomplete. PowerShell content writers require a scalar exact-parameter binding; literal redirections require matching AST node/owner/stream metadata, not legacy labels alone. Extended observations live in `baseline_stage5_extended_<os>.json`, with the immutable prior observation named `baseline_stage5_extended_before_54060c5_linux.json`. Optional Linux PowerShell parser/execution fixtures use `MODS_TEST_PWSH`; they do not replace Windows validation.
- Tool execution timeouts start after authorization completes.
- Windows command tools accept per-call `elevated: true`. Ordinary effect/target approval runs before the native UAC helper (`internal/tools/elevation_windows.go`); no elevation rule is persisted. Its one-shot named pipe checks peer PIDs, returns bounded stdout/stderr and exit status, and cancels the elevated command tree on disconnect. UAC consent counts toward the command timeout. Platform credential prompts use `InteractiveCredentialsForOS`; never promise Unix askpass on Windows. `TestUACIntegration` requires explicit `MODS_TEST_UAC=1` and a desktop consent response; default tests never trigger UAC.
- Path authorization: mutable filesystem/download tools expose `PrepareAccess`, resolve operation-specific canonical targets, and require an exact-call `WithExecutionGrant` after `requestApproval`. `preparedToolCall` shares arguments and intent between review and dispatch. Target changes trigger one fresh preparation/review before execution; continued changes fail closed. In-call path checks never fall back to cwd authority when a write grant is present. `WithAuthorizedDirs` remains the read/external-path context. Secrets may rebind content but cannot change prepared paths. These checks do not eliminate filesystem syscall races or sandbox shell processes.
- `internal/app` map: `mods.go` (model), `request_session.go` (tool-call orchestration), `review.go`+`review_summary.go` (approval UI/labels), `command_analysis.go` (tool input and result adapter; analysis algorithms and path-fact merge live in `commandanalysis/pipeline.go`), `provider.go`/`stream.go`/`stream_runner.go`, `prompts.go`, `tool_support.go`, `aliases.go` (re-exports approval/config/ui types into the app package).
- DB migrations: `PRAGMA user_version` and `schemaVersion` in `internal/session/db.go` skip migrations for current databases and reject newer schemas. Advance the version with each schema change; write it only after all migrations succeed. Version-zero databases run the existing guarded migrations. `internal/session/db.go` uses a replace-table pattern (`migrateApprovalRulesReplaceTable`) for primary-key changes (SQLite can't ALTER PK in place); guard each new column with `hasColumn` + a migration before the table is opened.
- Design docs for major subsystems live in `docs/superpowers/specs/` and `docs/superpowers/plans/`; consult them for context on non-trivial subsystems.
- Diagnosis evals: `internal/evals` scores a finished session transcript against the rubric in `docs/superpowers/specs/2026-10-17-agent-diagnosis-evals-design.md`; `internal/evals/cmd/score` copies `mods.db` before opening it. Always-on prompt policy lives in `internal/prompts` (`TestWorkflowHasSymptomDiagnosisPolicy`). Specialized procedures can be supplied as installed skills; mods ships no built-in skills.

- Prompt layering: `internal/prompts/identity.md` is the runtime-safety layer (approvals, input, denial) and `internal/prompts/workflow.md` is execution-layer workflow policy (planning, diagnosis, verification, self-help); neither file may emit its own headings because both render inside a titled system section. `TestIdentityStaysRuntimeSafetyOnly` and `TestWorkflowPromptsUseInlineLabels` guard that split. Sudo/Git credential policy is the conditional `prompts.InteractiveCredentials` fragment, injected only when the terminal can prompt for secrets (`TestSetupStreamContextInjectsInteractiveCredentials`); volatile `System info` renders in the final runtime-state layer so the instruction prefix stays cacheable across sessions. Tool mechanics belong to tool descriptions, not the tool-selection prompt (`TestToolDescriptionsCarryMechanicsThatLeftTheSystemPrompt`); script guidance is `prompts.ScriptPolicy`, shared by every tool description that recommends a script: simple commands and aggregation pipelines run directly; complex branching, loops, or reusable logic may use a script. Skills are loaded only from configured installation directories; there is no embedded skill catalog. Config editing guidance lives in the `mods_help` config topic. Code counting uses ordinary tool guidance; `TestAlwaysOnPromptsOmitCodeCountingProcedures` keeps specialized counting procedures out of always-on prompts.

- Prompt size: `proto.MeasurePromptSize` measures rendered system text plus complete provider-neutral tool-definition JSON, with per-section, description and schema breakdowns. It excludes conversation/media and does not estimate tokens. `TestAssembledPromptBudgets` exercises real app assembly and registration across normal/minimal, interactive, installed-skill and no-tool-provider fixtures; `TestFixedPromptFragmentsStayCompact` only bounds fixed text. Black-box evaluations default to normal mode with explicit minimal controls; `TestHarnessPromptModes` checks isolated config generation without API keys. Clarification evaluation uses `TestDeepSeekClarificationFirstRoundIntegration`: send real production prompts/tool definitions, record only the first model response, and never execute tool calls or invoke `CallTools` for ambiguous-target fixtures.

- Self-help identity prompt: `internal/prompts/identity.md` (runtime safety) and `internal/prompts/workflow.md` (execution workflow) carry only behavioral policy (not a catalog of flags or config keys). CLI flags are exposed to the model at runtime by introspecting the pflag set in `internal/cli/self_help.go` `selfHelpFlagGroups` (Name/Shorthand/Description/Advanced), which feeds the `mods_help` tool via `registeredSelfHelpFlags`; no entry in the prompt files is needed when adding a flag, but every public flag must be declared in `flagCategorySpecs` (`internal/cli/flags.go`) so it lands in the right group (uncategorized flags fall through to an `Other` bucket, and `TestFlagTableMatchesRegistration` fails when a registered flag is undeclared). `TestSelfHelpCatalogMatchesEveryPublicFlag` in `internal/cli/main_test.go` enforces that every non-hidden flag appears in the runtime catalog; `TestWorkflowHasSelfHelpPolicy` in `internal/prompts/prompts_test.go` guards the self-help policy text.

## Quirks
- Config precedence is intentionally `CLI flags > mods.yml > MODS_ env > defaults`; `config.Ensure` parses env before YAML so the file can override env.
- Custom OpenAI-compatible endpoints are configured as providers under `apis.<name>.base-url`; use `mods --config` or edit `mods.yml` instead of environment-variable auto-discovery.
- Custom web-search providers reject private/loopback targets unless `MODS_WEB_SEARCH_ALLOW_PRIVATE=1` is set; keep that SSRF guard covered by `internal/websearch` tests.
- The Task `install` path precedence is `BINDIR` > `PREFIX/bin` > XDG local bin > default (`/usr/local/bin`, or `%USERPROFILE%\.local\bin` on Windows); `DESTDIR` wraps the final path.
- CI runs on Ubuntu, macOS, and Windows; platform-specific code is split with build tags in `internal/tools`, `internal/platform`, and `internal/clipboard`.
- `DirAllow` and `RemoteAllow` approval rules are conversation-scoped (persisted in `approval_rules`, restored via `--continue`, not shared across conversations). Only explicit write-mode rules authorize writes; legacy empty-mode and read-mode directory rows are inert.
- All text files use Unix (LF, `\n`) line endings; no root `.editorconfig` yet so keep new files consistent.

## Command reviewability
- `internal/commandanalysis/command_constraint.go` exposes `HasReviewabilityConcerns` for diagnostic logging only. The separate P4 organization gate is app-owned and defaults off; once enabled it can return one typed not-executed result per user request only for a successfully analyzed built-in command with unproven effects and a high-confidence structure combination. Missing write-target coverage alone never qualifies. It does not parse/rewrite command text, grant permission, or skip ordinary approval of a replacement. Reads, saved rules, unknown effects outside the narrow candidate, denial, and ReviewNever keep the existing access policy. P4 state lives outside completion checkpoints and is shared across tool rounds, provider retries, and registry rebuilds; callbacks and runners capture the original request identity. New structure facts remain permission-neutral, and literal payload fragments are excluded from JSON/logging and deep-copied by Clone.
- `internal/commandanalysis/script_file.go` marks a literal script-file payload as `Reviewability.ScriptFilePayload`. This is syntactic metadata with no filesystem access and grants no permission. Existing scripts run unchanged once authorized; temporary script location does not authorize its execution effects. Related reads and aggregations may share a call or readable script; reuse data for subtotals and split calls when results or authorization require it.
- `review_pages.go` paginates shell, process, and download reviews and gates approval until all pages are displayed. There is no general script execution tool: simple commands and pipelines run directly, while complex or reusable scripts run by interpreter and path without being rewritten for review.
- P3 review adds explicit approve/deny/simplify actions; a human S requests reorganization, returns a typed not-executed error under the original call ID, and never dispatches or grants permission. Cancellation propagates context cancellation, not denial. `command_payload.go` prepares bounded literal `process_run` script previews only for interactive DecisionAsk calls, rechecks identity/content, and shares the single reapproval budget with target changes. Unsupported forms degrade explicitly; provenance remains unknown. Preview/digest never prove effects or immutable execution. P4 adds opt-in, request-scoped automatic organization (`off` by default, `once`); manual S remains independent of its budget. See `docs/superpowers/evidence/2026-10-27-command-generation-p3/README.md` and `docs/superpowers/evidence/2026-10-27-command-generation-p4/README.md`.
- `http_download` is a bounded structured batch tool using `netutil.SafeTransport` and ordinary filesystem path authorization. It uses the existing private-network opt-in, stops on failure, and preserves completed results.
- Shell `cwd` is literal read-only execution context, normalized before assessment; it must never be inferred as a write target without evidence.

## Native media inputs
- `proto.MediaAttachment` is the canonical ordered attachment model; legacy `Images` remains readable through `Attachments`/`NormalizeMedia`. New messages and tools write `Media`. Preserve source labels and deep-copy bytes in checkpoints.
- `fs_find_media`/`fs_read_media` and the image aliases share the scanner, reader and history budget in `internal/tools`. `ConfigureMedia` gates input kinds; external reads use the ordinary approval/path context.
- `internal/audio` validates bounded PCM WAV/MP3 without external executables. `stream.ValidateMedia` enforces shared raw bytes, image count, audio duration and per-audio inline limits; `ValidateMediaWireRequest` also bounds encoded request size.
- The existing `qwen` provider profile selects native audio/video encoding in Chat and Responses independently of model name; built-in Qwen selects it automatically, while custom gateways can configure it. Both project tool media to a user message after the complete tool-result group. Chat uses `input_audio.data`; Responses uses `input_audio.audio_url`. Keep Qwen continuation state distinct from DeepSeek/OpenAI state. Other adapters must reject audio explicitly until implemented.
- `--audio` is a non-persistent input flag, repeatable with `--image`. `internal/testutil/mediafixture` supplies synthetic parser fixtures, not speech-recognition evidence. Real-provider validation must use generated non-private speech and record results separately from mock protocol tests.

- `internal/video` validates bounded, non-fragmented H.264/AAC-LC MP4 using pure-Go `go-mp4`; no runtime transcoder. `internal/media` owns shared byte/duration/frame accounting; audio-bearing videos consume audio duration but bytes only once. Revalidate saved metadata against original bytes before transmission.
- `--video` and `fs_read_media` use the same `MediaAttachment` as images/audio. Qwen Chat sends `video_url.url`, Responses sends `input_video.video_url`, both with `fps: 2`. Capability checks include video audio; never turn unknown media into image blocks or drop sound. Label audio presence and sampled coverage; delivery is not proof of recognition.
