# 简化多媒体能力判断的修改计划

日期：2026-10-17。状态：已实施，验证通过。

本方案替代此前的用户声明方案：不新增 `input-modalities`，不新增协议 profile，不要求用户逐模型配置能力。

## 目标与取舍

模型能否理解媒体由用户选择和服务端判断。mods 只检查适配器是否实现了对应协议，以及媒体格式、大小、时长、音轨和历史累计预算是否有效。工具开放范围同样按适配器实现决定。

接受的取舍：纯文本模型也可能看到读图工具，读取后由服务端拒绝；不维护模型白名单、不做在线探测、不自动丢弃媒体或改用其他模型。

## 实施步骤

1. 删除 DeepSeek 图片白名单及 Chat/Responses 请求中的重复判断。保留 DeepSeek 请求格式和历史状态逻辑。
2. 将 Qwen 音视频编码、Responses 路由和历史续接从模型名称判断改为现有 `provider-profile: qwen`。内置 qwen 提供商自动选择该 profile；自定义网关可沿用已有的提供商级或模型级 profile 设置。显式指定其他 profile 时，不再被模型名覆盖。
3. 删除适配器配置中仅用于能力猜测的 Model 字段。模型 ID 仍随每个请求发送给服务端。保留现有 Capabilities 接口、工具门控和每轮媒体校验，不引入新的能力配置/解析层。
4. 本地错误明确指出适配器未实现该媒体协议；服务端拒绝按原链路返回。保留文件校验、路径授权、视频音轨检查、工具媒体分组和累计请求预算。
5. 更新 README、配置模板注释和 AGENTS.md。自定义网关若以前仅靠 Qwen 模型名触发协议，现在需设置已有的 `provider-profile: qwen`；普通内置 Qwen 用法无需修改。

## 验收

- 任意模型名在 qwen profile 下使用现有 Chat/Responses 音视频编码，包含工具往返与来源标签。
- DeepSeek 自定义模型名可以发送图片；模拟服务端拒绝在两个 endpoint 下均能返回，不在本地按名称拦截。
- 音视频能力按协议声明，普通 OpenAI profile 仍在 HTTP 前拒绝未实现的音视频传输。
- Qwen 历史状态按 profile/endpoint 保留与清理，不受模型名称影响；显式 profile 覆盖有效。
- 既有媒体格式、预算、音轨测试继续通过。
- 执行定向测试后运行仓库基线 check 和 test。

## 不在范围内

新增媒体协议、真实模型识别评测、转码或抽帧、音视频输出、自动修改用户配置、数据库迁移。

## 实施与验证结果

- 已完成上述步骤，复用现有 qwen profile，未添加配置字段或新 profile。
- 已移除 DeepSeek 图片白名单、Qwen 媒体模型名特判及 OpenAI 适配器 Config.Model 字段。
- 自定义模型名的图片、音频、视频工具往返测试通过；Chat/Responses 服务端拒绝回传及历史状态清理测试通过。
- 定向测试 `go test ./internal/openai ./internal/app ./internal/stream` 通过。
- 仓库基线 Task check（`go build ./...`）和 Task test（`go test ./...`）均通过；`git diff --check` 通过。
- 未调用真实提供商做识别测试；上述验证证明协议与控制流程行为，不证明具体模型的媒体理解能力。未更改用户配置，未提交或推送。
