# 用户请求的写目标预判

日期：2026-09-11

在正式执行任务之前，由当前配置的模型根据用户请求推断合理需要写入的目录
和远端目标。默认启用，无设置项；`auto` 执行，`always` 和 `never` 跳过。
`--minimal` 保留预判。工具不可用时没有可预授权的执行，直接沿用原流程。

## 流程

会话恢复、请求上下文和工具注册完成后，`prepareWriteTargets` 构建独立的
内部请求。输入 JSON 包含当前请求、用于指代消解的历史消息，以及 cwd、
home、OS。执行阶段的系统提示词、输出格式和 provider continuation 不混入预判。
历史和工具输出提供事实，不独立构成授权。由模型判断写入需求，不做关键词匹配，
不默认允许当前目录。

模型可直接返回 `{"write_dirs":[],"write_urls":[]}`，或者提出一批只读工具
调用。执行这批调用后，新建不含工具的最终请求。整个预判最多两个模型请求、
一批工具调用，30 秒超时，不自动重试。程序拒绝第二批调用，即使模型仍返回调用。
正式请求重试不重复预判。内部消息不加入正式会话；token 用量计入请求统计。

发现阶段复用现有非交互只读工具，排除问询和 todo 写入。shell/process 使用现有
静态评估和路径能力传递，unknown 回退不调用 LLM，不能证明只读就返回工具错误。
不会调用审批 UI，也不解析 secret_env 覆盖。允许跨目录只读检查。Git 的远端列表、
get-url、配置读取和当前分支查询由静态分析识别；配置修改等写操作不能执行。

短指令（例如续接会话的 `push`）仍表达完整的操作意图。存在隐含远端写、但地址
未知时，提示词要求先用可用的只读查询发现目标，而不是直接返回仅本地权限。
独立查询放在同一批次的不同调用中，避免一个不支持的查询使整条 shell 命令失效。

## 权限与回退

输出仅包含目录和网址。程序检查格式、移除无法解析的目标，使用已有规范化及
`RulesForDirs(..., AccessWrite)`、`RulesForRemoteOrigins` 生成普通规则，加入
当前 `reviewer.rules`。目录授权覆盖子树；远端按 scheme/host/port origin
匹配，例如 `git@github.com:owner/repo.git` 保存为 `ssh://github.com`，并非
单仓库授权。AI 可以返回部分已确定的目标，不需要为了缺失远端丢弃本地目标。

执行阶段的目标识别、审批矩阵和路径执行限制继续生效。全部实际写目标被规则
覆盖时才免审，额外目标或未知写目标仍走普通审批。规则通过现有 SaveSession
保存和恢复；新 session 不继承，`--no-save` 仅保留本次运行内的规则。不改表结构。

模型或工具故障、超时、非法输出、空目标均回退到原流程，已有规则不受影响。
用户取消则终止任务，不把取消当成预判失败后继续执行。预判状态只走现有操作状态
通道，自动允许的范围也记录在 debug 日志，不写入标准输出。

## 验证

覆盖直接结果、部分结果、空结果、格式错误、模型错误、取消、一次批次限制、
发现阶段拒绝写工具/未知命令/交互工具、跨目录读取、review-mode、minimal、
重试去重，以及保存恢复后本地与远端混合写免审、额外目标继续审批。

真实模型回归可显式运行：
`MODS_TEST_WRITE_TARGETS_LIVE=1 go test -tags integration ./internal/app -run TestWriteTargetsFollowupPushIntegration -count=1`。
该测试读取当前模型配置，在临时 Git 仓库验证续接 `push` 能发现不同于 fetch URL
的 push URL；只运行预判，不执行推送或正式任务。
