## 1. 执行原则和阶段依赖

目标是在正确性和确定性授权得到保持的前提下，让 AI 首次生成时优先选择只读、可证明且可理解的操作，尽量减少用户实际需要处理的命令审批，并兼顾模型往返和调用数量。减少审批是主要体验目标，不能仅靠把审批界面做得更易读来宣称完成。

能由受支持读取能力完成的查询任务，以正确完成且零人工命令审批为验收目标；确实需要修改的任务，应让查询尽量免审、必要写入目标明确。少量可证明只读调用可以优于一条需人工批准的大脚本，但不能机械拆为大量逐文件调用。不以关闭审查、扩大信任、省略必要修改、命令字符数或“原样例被自动放行”作为改善。

实施依赖：P0 基线 → P1 生成指导 → P2 结构/语义事实 → P3 审批与载荷预览 → P4 可选有限简化 → P5 真实评测与发布决策。P2 的纯结构展示和语义扩展分开提交，未完成某种语义不会阻止保守 unknown 展示。

P1–P3 不恢复自动纠正关卡。P4 才新增 `command-simplification: off | once`，首次发布默认 off。默认切为 once 必须有 P5 对照证据及独立变更，不能在评测过程中自动启用。

每阶段交付包括代码、相关测试、设计状态及实际结果。未执行、跳过、仅交叉编译与实机通过分别记录。当前工作树已有其他工作，实施前记录并避开它们，不重置或替用户提交。

## 3. P1：修改生成指导，不改变授权和执行

### 改动范围

优先修改：

- `internal/prompts/prompts.go`：ToolSelectionGeneral、ScriptPolicy 及平台指导。
- P1 精修补充 `QueryPolicy`，由 ToolSelectionGeneral/Minimal 共用；normal/minimal 实际组装各出现一次。minimal 保留原回答样式，不注入完整工作流，具体命令语义仍只放在工具描述。
- `internal/tools/guidance.go`：仍复用共享政策，避免额外重复文本。
- `internal/prompts/prompts_test.go`、`internal/tools/guidance_test.go`、`internal/tools/tools_test.go`：更新过度绝对的可选工具探测要求，保留提示分层不变量。
- `internal/app/prompt_budget_test.go`：只在确有必要且有分项解释时调整预算，不因文案膨胀直接放大总上限。

不修改 commandanalysis、approval、reviewMode、工具参数 schema 或工具执行路径。`identity.md`/`workflow.md` 不加入代码统计专用程序或冗长命令示例。

### 工作

1. 按设计 4.2–4.4 节形成一份简洁英文指令，明确只读优先、生成时可审查，落实最小充分结果、数据管道、结果依赖、复用数据及完整错误说明。
2. 将“禁止探测可选工具”改为有条件的一次批量能力查询；保持已有能力直接使用。
3. 明确纯查询不要附带创建脚本/输出文件、安装依赖或环境修改；必要写入与查询保持清楚边界，不把构建/测试等用途当作只读证明。不要按文件拆调用，不要把代码移到文件来缩短审批，不改写用户指定脚本。
4. 检查 normal/minimal、process/shell/Windows 组合实际组装内容，而不只检查字符串常量。
5. 用同一个分析器和授权版本运行 A/A1 提示对照，观察首次只读证明比例、查询零审批完成率和调用/往返；不凭单次生成决定最终文案。

### 出口

- 提示分层及完整 prompt byte budget 测试通过。
- 常驻提示无新的统计流程或模型/工具专用白名单。
- 字面参数、必要管道及原有相关读取合并能力保持。
- 提示同时覆盖“纯查询优先无副作用”和“必要修改仍需完成”；无需额外规划/提问/解析探测调用才能执行该选择。
- 只读查询夹具的首轮生成质量有单独记录；不能把新增 saved rule、临时豁免或审查关闭造成的审批减少归因于提示。
- 结果不足时可以说明，不鼓励抑制错误或编造汇总。

## 4. P2：结构化原因和有界聚合语义

### P2a：仅增加结构事实与诊断

首批落地：`Result.Structure` 记录 AST/IR 的控制流/脚本块深度、赋值节点、可见 shell 宿主与内联载荷、调用级未建模位置。最多 128 条位置诊断，支持 Clone 和旧结果空字段；不改 `Reviewability` 等级、授权和 UI。只复用现有节点与语义缓存，不增加 bridge 协议或解析。它是语法诊断，不是完整数据流/宿主载荷递归分析；自增状态分类等仍可后续扩展。

涉及 `reviewability.go`、`diagnostics.go`、`ps_bridge.go/.ps1`（只有现有 IR 不足时）、`result.go`、`parsed.go` 和相关测试。

工作：

1. 从共享 AST/IR 提取控制流深度、真实局部状态、内联载荷/宿主层次、已建模/未建模子树。
2. 为缺口建立稳定 code 和 source span/node ID；旧结果缺少位置时只显示命令级原因。
3. 增加有界结构元数据，补 Clone、确定性、空值和版本缺字段测试。
4. 保持 `HasReviewabilityConcerns` 诊断用途；不要重用为新拒绝函数。
5. 验证每 Analyze 主解析仍一次；新增遍历不触发命令执行、模型调用或额外文件探测。

出口：结构字段变化不会改变 `Effect`、`Targets`、`WriteCoverage` 和实际授权；有差异必须解释并移到独立 P2b 变更。

### P2b：逐项增加窄语义

首批落地：新增精确参数、单个字面文件路径的 `Import-Csv` 只读绑定及真实读取目标；已支持的单层 `Get-ChildItem → ForEach-Object { Get-Content } → Measure-Object` 只加回归，不增加任意循环解释。`ForEach-Object` 参数收紧到单个脚本块或精确 `-Process`，其余形式保持 unknown。具体支持表、安全负例及 52 条历史命令重放见 P2 验证记录。

2026-10-27 第二批：支持顶层 `(已证明读取的管道 | Measure-Object).Count/Sum/...` 标量属性投影。由精确参数产生输出字段证据，再通过 IR 节点所有权和源码位置绑定，不能推广为任意对象属性读取；静态过滤/分组复用既有规则。同步修复 Windows bridge 的 UTF-8 JSON 输入输出编码。新增控制场景及边界见 [第二批记录](../evidence/2026-10-26-command-generation-p2/PROJECTION.md)。原 52 条历史调用没有进一步审批减少，P3/P4 未启动。

涉及 `catalog_entries.go`、`semantics.go`、`readonly_ps.go`、相关 binding/组合代码及专门测试。

推荐顺序：静态属性过滤/投影 → 分组和计数 → 单层逐项读取 → 确实必要的局部纯表达式。每项先确认现有能力，已支持的只补回归；不因设计列出候选就全部重写。

每项必须交付：

- 精确语法、参数和输入来源支持表；明确哪些未知形式拒绝证明。
- 独立正例；同一结构插入写入、重定向、未知命令/选项和动态执行的负例。
- PS 真实 bridge 输入与 Go 组合测试；避免手工 IR 与实际 parser 不一致。
- catalog 修订及测试索引，新观察快照与逐项差异说明。
- 无 KnownDirs 回流授权、无非 nil 空写组丢失、无临时路径或候选权限提升。

不实现任意循环解释、不将方法名全局当纯函数、不为原样例放行而放宽所有脚本块。

## 5. P3：审批解释、人工简化和脚本预览

### P3a：解释与展示

修改 `review_presentation.go`、`review_summary.go`、`review_pages.go` 和对应 presentation/layout 测试。

- 显示已识别操作、真实读写目标、候选和未知原因，附可信源码位置。
- 区分 unknown effect 与 known write/incomplete coverage，去除重复警告。
- 显示实际 cwd/解释器/argv；源码保留完整并编号分页。
- 只依据分析证据形成摘要；不增加 LLM 安全解释请求或 justification 授权字段。
- 保留控制字符转义、Unicode 宽度、URL/秘密脱敏及 resize 后重新浏览要求。

出口：只改文案/展示不会改变 candidateRules 或批准结果；缺少事实时不输出推测性的“无写入”。

### P3b：人工请求简化的控制通道

本步骤为 P4 准备复用通道，可先与 UI 一起交付；它仅响应用户按 S，不自动产生反馈。

涉及 `messages.go`、`review.go`、`request_session.go`、活动状态/错误分类与 `stream.CallTool` 的契约测试。

- 将 reviewResponse 从 bool 改为明确枚举，零值拒绝，覆盖所有 switch/default。
- S 为独立于批准/拒绝的动作，返回有类型的未执行控制结果；不记录授权，不 dispatch。
- 工具结果对应原 call ID；沿用 `IsError=true` 的真实未执行语义，活动展示区分组织反馈与命令执行失败。
- 不重发已成功工具，不更换 provider call ID，不破坏同轮多个工具结果的完整性和媒体分组。
- N/取消行为不变；S 可以未读完页就选择，Y/A 仍要求完整浏览。
- Ctrl+C 继续通过现有任务取消事件/上下文传播，不能先返回普通错误让模型继续；完整 argv 页使用原始参数，不复用有损命令预览字符串。

出口：批准/拒绝/简化/取消均有真实分发测试，S 路径执行计数严格为零。

### P3c：脚本内容准备与复核

新增 app/tools 层的有界载荷准备组件（拟名 `command_payload.go`，不是当前已存在 API）。不把文件 I/O 放入纯结构分析，不新增脚本执行工具。

工作：

1. 从明确的字面脚本调用绑定实际文件和解释器；复用普通读取规则，不展开任意未知表达式。
2. 读取有界原始字节，记录身份、摘要、编码、cwd/argv 和预览内容；建议上限 256 KiB。
3. 全文页与摘要页共同决定可批准状态；无全文时准确标示降级能力。
4. 执行前复核脚本身份/内容及调用上下文；和既有目标重验证共享一次重新准备/审阅上限，持续或交替变化停止，已读页状态重新计算。
5. 若要区分本轮生成脚本，接入成功原生写入记录；没有可靠记录时标为 unknown，不能相信模型标签或临时目录。
6. 既有用户脚本无全文时保留明确的普通未知程序审批；可追踪生成脚本不提供伪装成完整审阅的批准。
7. 保持原路径和调用语义；不自动搬迁脚本，不宣称 digest 复核消除了 TOCTOU。
8. 只对本来需人工审批的调用准备预览；不在 ReviewNever 或已免审读取路径增加审阅阻断。预览有独立有界准备时间，保持实际工具 timeout/UAC 顺序。

出口：内容变化、缺失、权限错误、超限和不支持编码都有确定处理；发布文案准确区分预览+复核与不可变字节执行。强快照研究不阻塞基础预览，但不得把研究项写成已完成保证。

## 6. P4：请求级的一次自动简化

### 改动范围

- app 组织决策组件（拟名 `command_organization.go`）和请求生命周期状态。
- `request_session.go`、`completion.go`、`completion_checkpoint.go`、`mods.go` 中必要的状态传递；只增加请求级状态，不重构无关流式生命周期。
- 配置结构、Help、模板和测试：新增 `command-simplification`，默认 off，合法值 off/once，不增加 CLI flag。
- `internal/evals` 的新指标；旧失败/建议统计保持可读。
- 本阶段同步更新 AGENTS 的 diagnostic-only 条款、历史设计的取代说明及发布说明；保留其余授权约束。

### 工作

1. 实现纯组织决策：分析成功、来源允许、未证明效果和高置信结构问题必须同时满足。
2. 不把单程序 unknown、字符长度、花括号、分号或多个顶层动作单独用作触发条件。
3. 请求创建时初始化预算；回调工厂和 API 重试不能初始化第二份。
4. 原子消费自动机会；状态单调，不随 checkpoint 回滚，不因换工具或新命令文本重置。
5. 保守处理用户提供的完整载荷/来源不明；文件脚本首期不自动改写。
6. 在普通审批前返回复用 P3b 的有类型控制结果，保证原调用零执行且不进入后台重放队列。
7. 预算耗尽后只关闭自动反馈；未知仍走 requestApproval，不能把耗尽当作允许。
8. ReviewNever 跳过自动组织；minimal 与 normal 一致；非交互一次反馈后仍需审批则正常失败。
9. 取消/结束时关闭状态，旧 goroutine 不得操作新请求；同轮其他独立调用继续依原授权政策处理。

### 出口

- 同一请求并发、重试、恢复、工具重建至少三轮候选中，自动反馈总数仍不超过一。
- 人工 S 独立计数、不退还自动预算；拒绝不成为简化。
- 新调用完整重新分析/审批，没有继承原调用的“许可”。
- off 路径保持现有复杂命令普通审批；once 仅在指定候选上变化。
- 配置覆盖测试通过；帮助明确这是生成组织设置，不是权限模式。

## 7. P5：真实评测、平台验收与发布

### 对照设计

| 组 | 内容 | 用途 |
| --- | --- | --- |
| A | 实施前基线 | 确认问题频率与任务正确率 |
| A1 | 仅修改生成指导，分析器和权限与 A 相同 | 检查首次生成的只读证明比例和不必要审批是否改善 |
| B | 提示 + 事实/窄语义 + UI，自动简化 off | 测量语义支持对查询免审的附加收益及审阅理解成本 |
| C | B + once | 检查一次重新组织的实际净收益 |

固定模型、参数、工具、平台、权限设置和夹具，按交错顺序运行。每个关键场景每组至少 5 次，报告全部结果、范围和中位数；不要把各组混合统计成一条成功率。自动简化 off 不关闭只读优先提示，因此 B 本身就必须评估减少审批的效果。

主组 normal+auto。minimal 是明确对照；never 只用于区分审批影响，不代表生产安全模式。非交互 harness 不能模拟人工理解和用户批准；需要单独的模拟交互分发测试和人工终端验收。

不执行真实模型生成的未知任意脚本来获取评分：首轮生成可只分析；需要端到端时使用受控夹具、模拟危险工具或隔离环境，并保持审批语义。禁止 provider key/真实用户文件进入夹具和日志。

### 发布条件

- 确定性测试全部通过，完整 check/test 通过。
- 真实 Windows PS5.1/PS7、Linux/macOS POSIX 覆盖关键路径；缺失平台不得写“全平台完成”。
- 真实生成结果先满足任务正确性和口径，再评估查询零审批完成率、审批次数、理解成本及往返；没有靠省略用户要求或静默少计改善指标。
- 已证明存在受支持只读解法的查询夹具，合格调用必须无需人工批准；真实模型未达到该目标的运行逐项保留原因，不能删例或扩大权限。只有界面改善而生成/审批指标未改善时，不宣称只读优先目标已完成。
- 完成人工 UI 验收和脚本变化复核验证。
- C 若没有相对 B 的稳定净收益，保留 off，不调整阈值/评分规则掩盖失败。
- 默认改为 once 需要另行提交所用数据、失败样例、影响及回退说明；不是完成本计划的必要条件。

## 8. 测试矩阵

### 8.1 生成与分析

| 用例 | 必须断言 |
| --- | --- |
| 原样例 | 能指出结构/语义缺口；保守事实不丢；不可强求自动只读 |
| 清楚过滤/汇总、多操作数查询 | 保持一次调用能力；已证明读取不因外观拦截 |
| 纯查询存在受支持只读解法 | 首次生成优先只读工具/管道；无附带写入；实际授权无需人工批准 |
| 一个未知脚本与少量只读查询等价 | 不以调用少为唯一偏好；允许少量清楚查询，禁止逐文件机械拆分 |
| 查询混入无必要脚本创建、输出落盘或环境修改 | 评为生成质量问题，不能因临时豁免而算成只读优先成功 |
| 必要修改与前后查询 | 查询保持可证明只读；修改不被省略或伪称读取；按真实目标授权 |
| `git ls-files; git diff --stat` | 相关静态读取合并测试继续通过 |
| 长 argv、引号内分号/花括号、路径含 Unicode | 不用字符黑名单误判复杂结构 |
| 单程序构建/测试/安装、未知可执行文件 | 不因 unknown 单独请求重新组织 |
| 单层映射读取 | 子树及来源都被证明才是只读 |
| 过滤/聚合中插入写入、网络、后台、动态求值 | 不能被外层只读命令掩盖 |
| 对象方法/属性接收者不明 | 不按方法名或属性名推断纯度 |
| 解析失败/预算/取消 | 不吞错误，不执行载荷，不循环反馈 |
| Clone 与重复分析 | 新集合深拷贝；相同不可变输入结果确定 |

### 8.2 简化与授权分发

| 用例 | 必须断言 |
| --- | --- |
| 首个合格候选 | typed control result、call ID 正确、dispatch=0、自动预算变为 0 |
| 第二/第三个候选 | 无第二次自动反馈；unknown 继续需要审批 |
| 两个并发候选 | 自动反馈最多一个；无数据竞争 |
| API 重试/checkpoint/registry 重建/换工具 | 预算不退还、不重置 |
| 任务取消后新输入 | 旧回调不可触碰新预算，新请求拥有独立状态 |
| off / once × auto / always / never × normal / minimal | 严格符合设计模式矩阵 |
| 非交互 | 需要批准时明确 unavailable，不静默 never |
| 保存写规则、临时目录、外部读路径 | 组织机制不扩大权限，unknown 不借用规则 |
| Y / N / S / Ctrl+C | 分别执行一次/不执行/不执行并反馈/取消；零值和未知动作拒绝 |
| 原调用被重新组织 | 新调用自行评估；原调用永不补执行 |
| 同轮已有成功结果/媒体结果 | 不重复执行，不破坏工具组与附件对应关系 |
| 用户原样载荷、现有脚本、来源不明 | 不自动拆解，普通权限保持 |

### 8.3 UI 与脚本内容

| 用例 | 必须断言 |
| --- | --- |
| unknown 与 incomplete 已知写入 | 文案不同，不暗示已发现写入/没有写入 |
| source span 缺失/越界 | 回退命令级原因，不产生虚假行号 |
| 分页、长路径、中文、宽字符、终端 resize | 全文可读，Y/A 完整浏览限制仍成立 |
| 控制字符/ANSI/双向文本/URL/秘密 | 不能改写终端含义，不泄露秘密 |
| S/N/取消与选中项移动 | 不要求全页；焦点不会因解锁突然变成批准 |
| 脚本内容变化一次/持续变化/路径重绑 | 重新准备与审阅一次/停止/保守处理 |
| 脚本不可读、超限、编码问题、二进制 | 明确限制；不伪称完整源码审阅 |
| 相对导入、脚本路径身份 | 保持原调用，不偷偷拷贝到其他目录执行 |
| 预览与摘要日志 | 无原始秘密，内容摘要不是权限凭证 |

### 8.4 结果正确性与效率

- 行数：空白/注释/物理行定义，CRLF/LF、无末尾换行、空文件、多编码支持边界。
- 文件范围：tracked/untracked/ignore、依赖和生成目录、显式包含项，按声明口径核验。
- 聚合：文件数、总量、各分组一致，不能通过模型心算获得“差不多正确”的结果。
- 部分读取失败：明确不完整及错误；不能吞错后宣称全量。
- 明确要求详细报表：输出全部要求；含糊简单任务不强制附加多维报表。
- 效率：分别记录模型轮次、请求数、dispatch、审批、简化和重复采集；没有数据的字段记 unavailable。
- 审批负担：纯查询零人工审批完成率、每任务实际审批展示数、重新审阅次数、首次读取静态证明率，以及因 unknown 触发的查询审批。用户选择 S 也算人工介入；非交互 DecisionAsk 单列，不伪造实际展示事件。
- 归因：A/A1 固定分析器和权限检验生成改善，A1/B 检验窄语义附加收益；冷会话/保存规则分别统计。失败或遗漏不能算零审批完成，必要写入审批不作为只读生成失败。
- 人工：复核用户能否指出操作、目标、未知部分和批准范围；计时/评分是样本观察，不是自动安全判断。
