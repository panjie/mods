# mods 执行效率与反馈改进计划

## 目标与边界

以 omapop 字号调整会话为回归案例，减少无必要的交互、命令重试和验证支线，同时保持正常审批、路径授权和用户取消语义。

本计划不改模型选择、不增加运行时调用硬上限、不自动执行 shell 命令来验证编辑、不把 LLM 判断的只读结果升级为静态只读证明。不增加配置项或数据库迁移。下列清单保留原计划，实施结果见末尾记录。

## 已确认的现状

- `internal/app/command_preflight.go` 已跳过静态证明的读取及脚本文件，并将简化建议限制为每请求两次。建议仍会要求模型重发工具调用，因此存在交互和推理成本。
- `internal/approval/command_constraint.go` 明确不允许分类器的 read 结论清除 opaque 语法的提示。应保留此边界。
- `internal/tools/user_input.go` 的 question schema 使用 3000 字上限，普通问题的运行时校验上限却为 160。描述未清楚说明两种上限适用条件。
- 长度错误统一建议移入 placeholder，但只有 form 字段具有 placeholder，顶层问题没有。不能直接照此修正普通提问。
- `internal/tools/filesystem_write.go` 的 fs_replace 已有唯一匹配校验、匹配失败指导和替换次数反馈；不需要新增编辑工具。
- `internal/prompts/identity.md` 已要求直接执行明确请求、仅在必要信息缺失时询问，并区分观察、推断及未验证效果。应补充执行边界，而非重复堆叠规则。
- `internal/evals` 当前围绕症状诊断设计，不能把其中要求先澄清的规则直接套用于明确的修改请求。

## 阶段一：修正用户输入工具契约（P0）

涉及 `internal/tools/user_input.go`、`internal/tools/user_input_test.go`。

- [ ] 核对现有校验对 question 的 kind、单行/多行及长度的完整规则，列成测试表。
- [ ] 在 provider 可见的 question 描述中明确：普通单行问题最多 160 个字符；选择类多行问题的允许条件及上限以现有校验为准。共享常量生成描述，减少漂移。
- [ ] 按字段返回可执行的修正建议：顶层 question 提示缩短问题、将选项移入 options；仅有 placeholder 的 form 字段才建议移入 placeholder。
- [ ] 保持现有可用的多行选择问题，不通过一律将 schema 改成 160 来解决差异。仅在所有适配器支持时考虑条件 schema，本阶段不依赖它。
- [ ] 覆盖 160/161 边界、Unicode 计数、有效多行选择问题，以及顶层/表单错误提示的差异。

验收：有效请求兼容；模型能从工具描述预知主要限制；报错不再引导使用不存在的字段。不能承诺模型永不发出非法请求。

## 阶段二：定位并减少命令简化提示干扰（P1）

涉及 `internal/app/command_preflight.go`、对应测试，以及必要时的 shell assessment / approval 静态分析实现和 conformance 测试。

- [ ] 从原始会话取得完整 shell_run 参数，核对运行版本；日志中的省略命令不足以证明分类回归。没有原始数据时，将相似命令明确标为合成案例。
- [ ] 通过现有 assessment 测试链重现 `ls` 加文件名 find、find 分组、只读管道等情况，检查 effect、StaticRead、opaque、reviewability 及最终提示行为。
- [ ] 若确认安全的语法被错误降级，在静态分析层修复；不在 preflight 加命令名白名单或允许 classifier read 跳过所有提示。
- [ ] 为危险近邻补负例，包括 find -delete/-exec、写重定向、命令替换、未知语法及读写混合；检查权威路径事实仍完整保留。
- [ ] 缩短模型可见的提示：保留具体原因、一项相关建议、可保持原命令重发及不改写现有脚本的约束。避免每次返回大段通用说明。
- [ ] 保留两次建议预算、脚本豁免、ReviewNever 行为和耗尽后进入普通审批的机制。

验收：静态证明的读取不触发建议；未知或写操作仍走原有审批；已有脚本原样执行；精简提示不泄露目标或秘密。跨平台语法变化须在 POSIX/PowerShell 对应测试中验证。

## 阶段三：收紧执行策略，而非增加拦截（P1）

涉及 `internal/prompts/identity.md`、`internal/prompts/prompts_test.go`；必要时微调 fs_replace 的工具描述。

- [ ] 对明确的修改请求，允许模型选择可逆、低影响的常规实现细节；只有缺失信息会实质改变结果时才询问。与症状诊断的澄清规则明确区分。
- [ ] 指导小范围文本修改优先使用可用的 fs_replace / fs_apply_patch；工具缺席时允许 shell，不假设日志会话中一定暴露了原生文件工具。
- [ ] 编辑无差异时，先核对当前文本、匹配和引用，再提出权限或文件属性假设；进程退出成功不等于内容已修改。
- [ ] 验证针对尚未解决的风险：现有相关检查通过且无具体疑点即可收尾；不默认追加截图、基线 stash 或像素测量，也不禁止用户要求的视觉验证。
- [ ] 最终回复默认简短说明修改、验证及必要限制。不得把像素差异直接当作字号正确或实时生效的证明。
- [ ] 提示契约测试只防止策略丢失；不将字符串出现视为行为质量证据。

验收：保持必要澄清、视觉验证和复杂任务持续执行能力；通过阶段四的实际运行评测判断收益。

## 阶段四：建立明确修改请求的行为评测（P1）

涉及 `internal/evals/score.go`、`score_test.go`、评分 CLI 及独立的评测说明/fixture。先检查现有评分维度的复用范围，避免给诊断案例增加相反规则。

- [ ] 在临时目录建立可重置的最小 QML/Markdown 字号 fixture 和确定性的渲染/结构验证入口，不依赖用户插件目录或外部服务。
- [ ] 增加至少四个情景：明确的小改动、确实缺关键信息的请求、编辑匹配失败、测试失败需要继续排查。另设用户要求截图的对照情景。
- [ ] 自动记录工具调用数、交互询问数、无效参数次数、简化重试次数和修改结果；能可靠取得时记录耗时和 token。调用数作为比较指标，不作为运行时硬限制。
- [ ] 独立检查最终文件行为，包括标题字号层级；不能只通过“用了某工具”或“调用更少”判定成功。
- [ ] 人工复核无必要澄清、无依据诊断、验证是否过度和最终证据是否准确。不要仅依赖文本关键词判断这些语义。
- [ ] 同一模型和配置下进行多次修改前后对照，分别统计首次完成率、无效调用和调用数分布；记录模型标识、版本、采样参数及工具集。模型可用且有运行凭据时执行真实评测，离线测试不冒充模型行为验证。

验收：明确小改动减少无必要询问和失败重试，任务正确率不下降；必要澄清、失败后的继续排查及指定截图情景不退化。具体调用数阈值在基线采集后确定。

## 实施顺序与检查

按“阶段一 → 阶段二 → 阶段三 → 阶段四对照运行”推进；评测 fixture 与指标定义在修改提示前准备好。每阶段独立形成可审查改动，方便归因与回退。

运行相关包的定向测试：tools 的 UserInput/FilesystemReplace、app 的 CommandPreflight/CommandSimplification/ShellAssessmentConformance、approval 的结构约束，以及 prompts/evals。按实际测试名筛选，不为未改动模块机械重复测试。

完成后执行仓库基线：

```sh
go run github.com/go-task/task/v3/cmd/task@v3.51.1 check
go run github.com/go-task/task/v3/cmd/task@v3.51.1 test
```

涉及 shell 分类时依赖 Linux/macOS/Windows CI 验证平台差异；修改计划文档本身无需运行 Go 测试。

## 实施记录

- 已修正问题描述中的长度契约及错误提示，保留有效的多行选择问题；新增 Unicode 边界回归。
- 已通过合成命令复现 find 分组的静态识别缺口：mvdan 的未引用 Lit 保留反斜杠，原逻辑把 `\(` / `\)` 直接当成 find 参数。现在只在 find 只读判定中还原这两个语法 token，不改一般路径事实；引用的字面反斜杠保持原样。补充写操作、动态参数与引用反例。原始完整会话命令仍不可得，不宣称是原会话的精确重放。
- 已压缩通用简化建议，并删除 opaque 提示中提前声称“正在请求审批”的不准确说法；预算、脚本豁免、审批机制不变。
- 已补充常规实现选择、无差异编辑排查、适度验证和简短汇报策略。运行时提示预算从 9.25 KiB 调整为 10.25 KiB，以覆盖新增策略。
- 已新增五种修改情景及真实 provider 测试入口、独立的字号夹具检查和会话指标。修正原评分器把 tool 结果元数据重复计为调用的问题。
- fs_replace 沿用唯一匹配反馈，并新增内容不变时的明确反馈且跳过重写，覆盖 LF/CRLF；没有添加自动 shell 后检查。
- 当前没有可用的匹配 provider key，真实模型情景均明确跳过。修改前后多次对照、真实截图核实及跨平台 CI 仍需对应运行环境；不以离线测试替代这些证据。
- Task v3.51.1 自身的依赖编译在 `google.golang.org/grpc/internal/transport` 报 `undefined: http2.TrailerPrefix`，尚未执行到项目 check。改用 Taskfile 中等价的 `go build ./...` 和 `go test ./...`，根模块构建及全部测试通过，不修改无关依赖。
